# Collaborer à plusieurs sur un même projet (GitLab)

Après avoir préparé votre propre carnet de recettes, il est temps de **passer en cuisine à plusieurs** !
Dans cette partie, vous allez former des **groupes de 2 à 4 personnes** pour créer **un livre de recettes collaboratif**.


## Création de la brigade

Dans chaque groupe, désignez un **chef de projet** — le _chef cuisinier_, si vous préférez.
C’est cette personne qui aura la responsabilité de créer le dépôt commun au sein d’un groupe privé du sous-groupe  [Brigades](https://gitlab.in2p3.fr/git-kitchen/brigades) sur GitLab. Ensuite concertez-vous avec vos camarades pour choisir un nom de groupe original et représentatif de votre brigade.

Le _chef cuisinier_ devra alors se signaler (pour que nous puissions nous assurer de l'équilibre des groupes). Il pourra dès lors créer le sous-groupe de sa brigade dans le sous-groupe [Brigades](https://gitlab.in2p3.fr/git-kitchen/brigades).

Pour cela :

1. Aller sur la page du sous-groupe [Brigades](https://gitlab.in2p3.fr/git-kitchen/brigades)

2. Cliquer sur **New subgroup**

3. Remplir les champs :

  - **Subgroup name** : le nom de votre brigade (ex. `La Bonne Humeur`)
  - **Subgroup URL** : sera automatiquement généré à partir des groupes parents et du nom de la brigade
  - **Visibility Level** : `Private` (afin de rester entre cuisiniers avertis, hérité du groupe parent) 

4. Cliquer sur **Create subgroup**


## Inviter les rédacteurs et gérer les permissions

Le _chef cuisinier_ peut maintenant inviter ses camarades à rejoindre le sous-groupe de la brigade. Pour cela, après avoir navigué jusqu'au sous-groupe nouvellement créé, il faut selectionner dans la barre latéral l’onglet Manage > Members, puis inviter les membres via le bouton bleu **Invite members** en haut à droite.

Depuis cette interface, le chef cuisinier pourra ajouter les identifiants GitLab de ses camarades et leur attribuer le rôle qui convient.

| Rôle GitLab          | Permissions principales                                                 | À utiliser pour…                 |
| -------------------- | ----------------------------------------------------------------------- | -------------------------------- |
| **Developer**        | Peut créer des branches, des commits et des _merge requests_            | Vos rédacteurs de recettes       |
| **Maintainer**       | Peut fusionner les _merge requests_ et gérer la configuration du projet | Le chef de projet                |
| **Reporter / Guest** | Lecture seule, utile pour tester ou relire                              | Invités ou correcteurs éventuels |


## Créer le livre de recettes collaboratif

Maintenant que le sous-groupe de la brigade est créé, il est temps de créer le dépôt GitLab qui contiendra le livre de recettes collaboratif. Pour ce faire, le chef cuisinier suit **exactement les mêmes étapes** que dans le TP précédent :

1. Aller sur le [groupe GitLab de sa Brigade](https://gitlab.in2p3.fr/git-kitchen/brigades)

2. Cliquer sur **New project → Create blank project**

3. Donner un nom au projet, par exemple :

   ```
   le-livre-de-la-bonne-humeur
   ```

   ou

   ```
   le-livre-de-la-patate-douce
   ```

   (Faites preuve d’imagination et discutez-en avec vos camarades !)

4. Ajouter une description, par exemple :
   _« Un livre collaboratif regroupant nos meilleures recettes maison. »_

5. Choisir la visibilité **Private** (afin de rester entre cuisiniers avertis).

6. Cliquer sur **Create project**[^main-branch].

[^main-branch]: Par convention, la branche principale reste `main`, comme dans vos projets précédents.

Une fois le projet créé, le chef de projet aura accès à une page vide, prête à accueillir les futures créations culinaires du groupe. Les membres de la brigade hériteront automatiquement des permissions de contribution définies précédemment au niveau du sous-groupe.

Le chef cuisinier peut aussi s'assurer que la branche principale `main` est protégée (onglet **Settings → Repository → Protected branches**), afin que toutes les modifications passent par des _merge requests_ et éviter ainsi les accidents.


## Organiser le travail avec les tickets (issues)

Avant de commencer à ajouter et modifier vos recettes, nous allons apprendre à **organiser le travail avec des tickets**.

Les _issues_ (ou **tickets**) peuvent servir à proposer des idées, documenter des problèmes ou suivre des tâches à accomplir. Par exemple, chaque membre de la brigade peut créer un ticket pour :

- une **nouvelle recette** à ajouter (« Créer la recette du fondant au chocolat »),
- une **correction** à apporter (« Erreur sur les proportions du gâteau au yaourt »),
- ou une **proposition d'amélioration** (« Ajouter la photo manquante à la recette des crêpes »).

Chaque ticket peut inclure plusieurs sous-tickets pour mieux découper les tâches à accomplir et potentiellement répartir la charge de travail.

### Création d’un ticket

Chaque membre du projet doit maintenant créer au moins un ticket. Il est important de discuter en amont des tâches à accomplir et de la façon dont vous souhaitez les répartir.

1. Rendez-vous dans l’onglet **Issues → New issue**.
2. Remplissez le titre, par exemple « Ajouter la recette de la tarte aux pommes classique »

3. Dans la description, précisez :

   - Le type de recette ou de correction
   - Les contraintes (ex. « prévoir une version sans gluten »)
   - L’auteur pressenti (si décidé à l’avance)

4. Cliquez sur **Create issue**.

Le ticket s’affiche maintenant dans la liste des _issues_ du projet, visible par tout le groupe.

> Astuce : vous pouvez aussi utiliser les _labels_ GitLab pour catégoriser vos tickets, par exemple :
>
> - `nouvelle-recette`
> - `correction`
> - `a-revoir`
> - `idée`

## Cloner le dépôt du livre en local

Chaque rédacteur (y compris le chef) doit maintenant **cloner le projet** sur sa machine pour pouvoir y ajouter des recettes.

Rendez-vous sur la page du projet, cliquez sur le bouton **Code → Clone with SSH**, copiez l’URL, puis exécutez la commande suivante dans votre terminal (en adaptant l’URL à votre projet !) :

```bash
git clone git@gitlab.in2p3.fr:git-kitchen/brigades/ma-brigade/le-livre-de-la-bonne-humeur.git
cd le-livre-de-la-bonne-humeur
```

Créez au besoin un dossier `recettes` s’il n’existe pas encore :

```bash
mkdir -p recettes
```

À ce stade, tout le groupe travaille à partir du même dépôt GitLab, synchronisé via la forge.


## Du ticket à la merge request : le flux de travail collaboratif

Nous allons maintenant relier **tickets** et **branches Git** dans une méthode de travail claire et efficace.
Chaque nouvelle recette ou correction issue d’un ticket correspondra à une **branche de travail**, suivie d’une **merge request**.

### Étape 1 — Se synchroniser avec `main`

Avant toute modification, récupérez la dernière version du livre :

```bash
git pull --ff-only origin main
```


### Étape 2 — Créer une branche liée à un ticket

Choisissez un ticket (par exemple _Issue #3 : Ajouter la recette du tiramisu_), puis créez une branche nommée en fonction de ce ticket :

```bash
git checkout -b issue-3-recette-tiramisu
```

Vous pouvez relier automatiquement le ticket à la future merge request en mentionnant son numéro dans le nom de branche ou dans votre message de commit.


### Étape 3 — Ajouter la recette ou la correction

Créez ou modifiez le fichier correspondant dans le dossier `recettes/`, puis :

```bash
git add recettes/tiramisu-classique.md
git commit -m "Ajout de la recette du tiramisu (fixes #3)"
git push --set-upstream origin issue-3-recette-tiramisu
```

> 🔗 En ajoutant `fixes #3` dans le message du commit ou de la MR, GitLab fermera automatiquement le ticket une fois la merge request fusionnée.


### Étape 4 — Créer une merge request

Une fois votre branche publiée, GitLab vous proposera automatiquement de créer une **merge request** (MR).
C’est une demande d’intégration de votre recette dans le livre principal (`main`).

1. Cliquez sur le lien suggéré dans le terminal ou allez dans
   **Repository → Branches → [New merge request]**
2. Remplissez les champs :

   - **Title** : « Ajout de la recette du tiramisu classique »
   - **Description** : indiquez le contexte, par exemple « Recette testée le 6 octobre avec succès »

3. Assignez votre MR au chef de projet (le maintainer).
4. **Labels** : `nouvelle-recette`
5. Cliquez sur **Create merge request**.

Le chef de projet ou un autre membre du groupe pourra alors relire, commenter ou fusionner votre contribution dans le livre principal.


## 6. Fusion, mise à jour et suppression de branche

Une fois la MR acceptée et fusionnée, il est temps de nettoyer votre espace de travail :

```bash
git checkout main
git pull --ff-only origin main
git branch -d issue-3-recette-tiramisu
```

Vous pouvez ensuite recommencer pour une nouvelle recette, une correction, ou une mise à jour d’image.


## À vous de jouer !

Répartissez les rôles, et commencez à compiler vos meilleures recettes.
Créez vos branches, rédigez vos _merge requests_, et voyez votre livre de cuisine prendre forme page après page.

Et souvenez-vous :
 - une bonne branche est une branche dont la durée de vie reste courte
 - un bon commit explique clairement et de façon concise ce qui a été fait
