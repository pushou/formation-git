# Créer et inspecter un pipeline GitLab CI — Vérification d’orthographe avec Grammalecte

Dans cette étape, vous allez mettre en place une intégration continue sur GitLab qui vérifie automatiquement l’orthographe et certaines règles typographiques de vos recettes rédigées en Markdown à l’aide de [Grammalecte](https://grammalecte.net/).

### Objectifs

* Ajouter un fichier de pipeline `.gitlab-ci.yml` dans votre dépôt.
* Installer et exécuter Grammalecte en CI pour analyser `recettes/**/*.md` (c’est-à-dire tous les fichiers Markdown du dossier `recettes/` et de ses sous-dossiers).
* Faire échouer le pipeline si des erreurs sont détectées.
* Visualiser le pipeline et consulter les rapports dans l’interface GitLab.

---

## Pré-requis

* Un dépôt GitLab fonctionnel (votre carnet de recettes individuel, puis votre livre collaboratif).
* Au moins une recette en Markdown dans le dossier `recettes/` (ex. : `recettes/crepes-classiques.md`).

---

## Étape 0 — Préparation

Avant de commencer, assurez-vous d’avoir synchronisé l’ensemble de votre travail avec le dépôt distant sur GitLab.
Créez ensuite une branche dédiée à cet exercice, par exemple :

```bash
git checkout -b ci-grammalecte
```

---

## Étape 1 — Créer le fichier `.gitlab-ci.yml`

À la racine de votre dépôt, créez un fichier nommé `.gitlab-ci.yml`.
Ce fichier décrit les différentes étapes que GitLab exécutera automatiquement sur ses *runners*.
Il vous permettra d’automatiser diverses tâches, ici la vérification orthographique et grammaticale.

Dans un premier temps, nous allons définir une seule étape appelée `lint`, chargée de vérifier la qualité du texte.

<details>
<summary>Exemple de structure minimale</summary>

```yml
stages:
  - lint
```

</details>

Notre étape `lint` contiendra un seul *job*, nommé `grammaire_et_orthographe`, qui analysera le contenu des recettes.
Comme Grammalecte est un package Python, nous utiliserons une image Docker basée sur Python.

<details>
<summary>Définition du job</summary>

```yml
grammaire_et_orthographe:
  stage: lint
  image: python:3.12
```

</details>

Il faut maintenant installer l’utilitaire qui effectuera la vérification.
La commande d’installation est la suivante :

```bash
python -m pip install git@gitlab.in2p3.fr:sonny.lion/grammalint.git
```

Nous plaçons cette commande dans un bloc `before_script`, ce qui permet de séparer proprement l’installation de l’exécution du code (c’est uniquement une question de clarté).

<details>
<summary>Ajout de la phase d’installation</summary>

```yml
grammaire_et_orthographe:
  stage: lint
  image: python:3.12
  before_script:
    - python -m pip install git@gitlab.in2p3.fr:sonny.lion/grammalint.git
```

</details>

Nous pouvons enfin ajouter la commande qui lance la vérification d’un fichier Markdown.
Par exemple, pour vérifier une recette donnée :

```bash
python -m grammalint -i recettes/crepes-classiques.md
```

Pour analyser automatiquement tous les fichiers Markdown du dossier `recettes/`, on peut écrire :

```bash
python -m grammalint -i recettes/**/*.md
```

Ce qui donne au final :

<details>
<summary>Pipeline complet</summary>

```yml
stages:
  - lint

grammaire_et_orthographe:
  stage: lint
  image: python:3.12
  before_script:
    - python -m pip install git@gitlab.in2p3.fr:sonny.lion/grammalint.git
  script:
    - python -m grammalint -i recettes/**/*.md
```

</details>

## Étape 2 — Commit, push et inspection du pipeline

Une fois votre fichier `.gitlab-ci.yml` créé et vérifié localement, il est temps de le tester directement sur GitLab en exécutant le pipeline.

### 1. Enregistrer et envoyer les modifications

Commencez par valider votre travail et envoyer la nouvelle branche sur le dépôt distant :

```bash
git add .gitlab-ci.yml
git commit -m "CI: vérification d’orthographe avec Grammalecte"
git push origin ci-grammalecte
```

💡 *Astuce :* assurez-vous d’être bien sur la branche `ci-grammalecte` avant de pousser, grâce à la commande `git status`.

---

### 2. Ouvrir le pipeline sur GitLab

* Connectez-vous à l’interface web de votre projet GitLab.
* Allez dans le menu latéral **CI/CD → Pipelines**.
* Vous devriez voir apparaître un nouveau pipeline, déclenché automatiquement par votre *push* sur la branche `ci-grammalecte`.

Chaque pipeline correspond à une exécution de votre fichier `.gitlab-ci.yml`.
Dans ce cas, il contiendra une seule étape : **`lint`**, et un seul job : **`grammaire_et_orthographe`**.

---

### 3. Consulter les logs du job

Cliquez sur le nom du job `grammaire_et_orthographe` pour afficher les détails d’exécution.
GitLab ouvrira une interface affichant les logs en direct ou après exécution.

* Les premières lignes montrent le téléchargement de l’image Docker `python:3.12`.
* Ensuite, GitLab installe le paquet `grammalint` (Grammalecte adapté au CLI).
* Enfin, il lance l’analyse des fichiers Markdown dans `recettes/**/*.md`.

Si tout se passe bien, vous verrez un message du type :

```
Analyse du fichier recettes/crepes-classiques.md
...
Job succeeded
```

Dans le cas contraire, le job échouera (`Job failed`) et les erreurs détectées apparaîtront dans les logs, par exemple :

```
...
```

---

### 4. Corriger et rejouer le pipeline

Si des erreurs sont signalées :

1. Corrigez vos fichiers Markdown localement.

2. Commitez les modifications.

3. A chaque nouveau *push*, GitLab déclenchera automatiquement un **nouveau pipeline**.

## 3. Conditionner l’exécution du job

Par défaut, le job s’exécute à chaque *push* sur n’importe quelle branche.
Vous pouvez restreindre son exécution à un sous-ensemble de branches (via des expressions régulières), au demande de fusion, ou encore à la branche principale `main`.

Ici nous allons limiter l’exécution à la branche principale `main` et aux demandes de fusion (merge requests) visant `main`.
Ajoutez le bloc `rules:` suivant à votre job :

```yml
  rules:
    - if: $CI_COMMIT_BRANCH == "main" # Exécuter sur main
    - if: $CI_MERGE_REQUEST_TARGET_BRANCH_NAME == "main" # Exécuter pour les MR vers main
```

Tentez l'expérience de pousser des modifications sur la branche `ci-grammalecte` : le job ne s’exécutera pas.


Pour que le job s’exécute de nouveau, ouvrez une *merge request* (MR) de `ci-grammalecte` vers `main` et consultez l’onglet **Pipelines** de la MR.

Une fois le pipeline vert, vous pouvez fusionner la MR. Vous devriez voir un nouveau pipeline s’exécuter sur `main`.

## 4. Artefacts et rapports d’analyse

Les artefacts sont des fichiers générés par un job et stockés par GitLab. Ils peuvent être consultés et téléchargés depuis l’interface web.
Ils sont utiles pour conserver des rapports d’analyse, des résultats de tests, ou tout autre fichier produit par le job.

Pour générer un rapport JSON par recette, vous pouvez modifier la commande dans le bloc `script:` de votre job :

```yml
  script:
    - python -m grammalint -i recettes/**/*.md -o report.json"

```

Puis ajoutez une section `artifacts:` pour indiquer à GitLab de conserver ce fichier :

```yml
  artifacts:
    paths:
      - report.json
    expire_in: 1 week  # Durée de conservation (optionnel mais recommandé pour éviter d'encombrer le stockage)
```

Le fichier `report.json` sera alors disponible en téléchargement depuis l’interface GitLab, dans la page du job.

A noter que les artefacts peuvent aussi être utilisés pour transférer des fichiers entre différents jobs dans un pipeline.
